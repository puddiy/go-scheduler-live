# Аудит точности runtime/trace — 9 октября 2026

Проект воспроизводит записанное выполнение обычного Go. Проверка выполнена на
Go 1.26.2 с `golang.org/x/exp` версии
`v0.0.0-20260611194520-c48552f49976`. Собственная сборка runtime не требуется.
Внутренности очередей, которые trace не раскрывает, остаются неизвестными.

## Исправления

| Область | Проверенный результат |
|---|---|
| Начальные G | Running, Runnable, Waiting и Syscall сохраняются как первое наблюдаемое состояние; это не создание G |
| Первые P | Undetermined/NotExist→Idle сохраняется; одинаковые состояния не выдаются за приобретение P |
| Время | Отсчёт начинается с первого сырого события; `trace_end` сохраняет конец полной записи |
| GOMAXPROCS | Все записанные значения сохранены; отображаются текущая метрика и неактивные P после уменьшения |
| Создание и пробуждение | `actorGid` берётся из executing G контекста, отдельно от target G; неизвестный контекст явно равен −1 |
| M | Привязка к G только в Running/Syscall; creator/waker M не присваивается target G |
| Syscall | G сохраняет M; P может оставаться в _Psyscall до release. Возврат в Runnable не доказывает отсутствие свободного P |
| P-stop | Не устанавливает инициатора остановки или будущего владельца; новая привязка показана только после записанного acquisition |
| cgo | Создание G сразу в Syscall поддерживается; завершение удаляет контекст syscall до повторного использования M |
| Очереди и stealing | Удалены эвристика stolen, локальные очереди и их фиктивная ёмкость. Все Runnable находятся в общей области без назначения P |
| GC | Уже активная фаза не получает выдуманное начало; частичные фазы не увеличивают счётчик полных mark-фаз |
| STW | Интервал координации runtime не подменяет реальные состояния G общей заморозкой; не каждый STW относится к GC |
| Куча | Показаны allocated heap objects / soft GC goal, включая >100%; нулевые метрики сохраняются в JSON |
| Рендер | G/M меняют позиции одновременно с событиями. Пауза останавливает декоративные движения; смерть не перезапускает fade на каждом кадре; seek назад восстанавливает scale/alpha |
| Счётчики | Учитывают все наблюдаемые живые G; `+N` означает лимит рисования, а не размер очереди |
| Повтор запуска | Новая конфигурация записывает trace; повтор воспроизводит кэш. Статическая версия использует заранее записанные данные |

Длительность состояния, начало которого было до первого наблюдения, помечается
как нижняя граница `≥`. Длительность жизни неизвестна для G, уже существовавших
в начале записи. Старт trace отфильтрован из GC-индикации как артефакт записи.
Старые JSON с `stolen` поддерживаются, но этот флаг не изображается как факт.

## Проверка

`TestSchedulerInvariants` на всех шести сценариях сравнивает каждое
нормализованное изменение состояния G, его timestamp, ID и executing actor с
независимым `x/exp/trace.Reader` исходной записи. Начальные Running/Syscall
участвуют в проверке ограничений P/M. Это проверяет соответствие записи;
расписание следующих запусков может отличаться.

Регрессии Go покрывают первые состояния, новый Idle P, отсутствие выдуманных
steals, GOMAXPROCS, конец записи и JSON-значение 0. Frontend регрессии проверяют
fold, частичные диапазоны, счётчики, layout, causality, cgo, клавиатуру и pause.

Браузерные harnesses:

```bash
SHOOT_URL=http://localhost:5173 node web/scripts/verify-controls.mjs
SHOOT_URL=http://localhost:5173 node web/scripts/verify-fidelity.mjs
GOCACHE=/tmp/gmp-go-cache make ci
cd web && npm run build
```

`verify-fidelity.mjs` проверяет совпадение позиций G/M и счётчиков с playhead в
31 точке каждого сценария, паузу, death/seek, STW, фокус загрузки и ширины
375/768/1440 px, доступность кнопки закрытия вводной карточки и точное попадание
кликов по краям timeline в начало/конец trace. Скриншоты проверяются визуально,
помимо автоматических assertions.

Финальный локальный результат: `make ci` прошёл (166 frontend-тестов,
Go tests/vet/lint), `go test -race ./...` прошёл, production build прошёл,
control contract — **38/38**, fidelity contract — **27/27**, inspector contract — **27/27**, ошибок браузера нет.
Скриншоты desktop и mobile просмотрены. Новый fidelity harness включён в CI.

## Граница достоверности

Heap-метрики прорежены до одной точки на имя за 2 мс; GOMAXPROCS не прореживается.
Sweep, mark-assist, загрузка CPU mark-воркеров, жизненный цикл запаркованных M,
netpoller и sysmon не показаны отдельными сущностями. Позиции — схема состояний,
а не физическое движение. Ленты, крыши, робот, плитки кучи и позы — декорации.

Для старых trace без метрики GOMAXPROCS число P является нижней границей по ID.
Частично записанные диапазоны сохраняют известную часть; полного начала/конца
проект не придумывает. Лимиты загрузки остаются 16 МБ, 200 000 нормализованных
событий и 8 P. Полную внутреннюю картину очередей обычный trace не предоставляет.

## Источники

- [Go 1.26.2 runtime/proc.go](https://github.com/golang/go/blob/go1.26.2/src/runtime/proc.go): `stopTheWorldWithSema`, `startTheWorldWithSema`, `entersyscall`, `exitsyscall`, `runqsteal`. STWStart записан до остановки последнего P; STWDone — после возобновления P.
- [x/exp/trace event.go, pinned commit](https://github.com/golang/exp/blob/c48552f49976/trace/event.go): executing context `Event.Goroutine/Proc/Thread`, target `StateTransition.Resource`, состояния G/P и RangeActive.
- [x/exp/trace order.go, pinned commit](https://github.com/golang/exp/blob/c48552f49976/trace/order.go): первое наблюдение P и разбор syscall transitions.
- [runtime/trace](https://pkg.go.dev/runtime/trace): записываемые события и формат execution trace.

## Инспектор G/M/P

Инспектор отображает тот же полный снимок `stateAt`, что и сцена. Для G в
syscall отдельно показан исходный P; mid create/unblock не становится
привязкой целевой G. M показывает экранный псевдоним и `trace.ThreadID`;
отсутствие связей не трактуется как парковка или завершение потока.
История показывает последние 12 событий до текущего времени. JSON
содержит нормализованные поля, а не полный исходный бинарный event.

«Назад» и «Шаг» переходят к предыдущей/следующей временной отметке. Все
события на одной отметке применяются вместе; выбор отдельной строки
меняет показанные поля, сохраняя полный снимок на этой отметке.
Регрессии покрывают creator/unblocker context, syscall origin, неизвестные
M, будущие G, смену trace, повторное открытие и pause/seek во время playback.
